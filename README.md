# Veil · development MVP

**Текстовий месенджер без номера телефону: нативні iPhone та Android клієнти, Signal E2EE, зашифрована історія на пристроях.** На основі наданого Echo design, під назвою Veil.

> **Неаудитований прототип, не для справжніх секретів.** Код і наявні тести не означають підтверджену безпеку. Актуальні результати перевірок — у `docs/BUILD_STATUS.md`. iOS потребує macOS/Xcode; вихідні коди не є підписаним IPA.

## Що входить у v0.1

- Реєстрація з клієнтським UID і `@handle`, без телефону, email та завантаження контактів.
- Один пристрій на акаунт, текстові чати 1:1, пошук за точним handle.
- **Офіційний libsignal** на клієнтах; немає саморобної реалізації Signal чи шифрування повідомлень на сервері.
- Пінування identity key та порівняння числового відбитка незалежним каналом. До перевірки — TOFU, не доведена особа співрозмовника.
- Шифроване локальне сховище з пристроєвим ключем Keychain / Android Keystore, без cloud backup.
- Локальна черга відправки; повторюється той самий шифротекст, не повторне шифрування.
- Relay тимчасово тримає шифротекст офлайн-одержувачів, видаляє після ACK або TTL, типово 30 днів. Історія чатів не є серверним архівом.

**Не входить:** групи, вкладення, дзвінки, push/APNs/FCM, кілька пристроїв, recovery phrase, резервні копії, sealed sender, key transparency, гарантія 10 000 користувачів. На мобільному доставка перевіряється у відкритому застосунку; системні обмеження фону не обходяться.

## Важливо про «все зберігається на пристроях»

Приватні ключі та розшифрована історія залишаються на пристроях. Для офлайн-доставки, як у PDF, на сервері тимчасово є **зашифровані конверти**. Також сервер має UID, handle, публічні ключі та хеші токенів. Якщо потрібен буквально нуль збережених конвертів на сервері, знадобиться інший режим із одночасною присутністю обох клієнтів; це не поточна модель.

Оператор relay бачить відправника/одержувача, IP, час і розмір обміну. E2EE не дорівнює анонімності. UUIDv7 містить час створення, а handle може ідентифікувати людину. Компрометація розблокованого пристрою обходить захист E2EE.

## Relay локально

Python 3.11+; сервер не потребує third-party Python бібліотек:

```sh
python3 -m unittest discover -s server/tests -t server -v
python3 server/build_zipapp.py
python3 dist/veil-relay.pyz --host 127.0.0.1 --port 8787 --db "$HOME/.local/share/veil-relay/relay.sqlite3"
```

За потреби дотримуйтеся команд у `server/README.md`, який описує конкретний CLI. Не відкривайте plain HTTP у спільну мережу. Телефонам потрібна доступна HTTPS-адреса вашого relay; `localhost` на телефоні не вказує на комп'ютер.

## Мобільні збірки

- **Android APK:** `docs/ANDROID_BUILD.md`.
- **iPhone:** `bash scripts/ios-build.sh simulator`, далі XCTest та signing на власному Mac. Підписаний IPA не можна замінити симуляторною `.app`.
- CI workflows надані як конфігурація, а не як уже виконані віддалені збірки.

Нічого не розгортається публічно автоматично. Видалення застосунку/втрата ключа може назавжди втратити акаунт та історію — recovery у MVP немає.

## Відмінності від PDF

PDF — план повної системи, а не обіцянка реалізувати всі фази за один сеанс. MVP використовує зашифрований атомарний vault замість SQLCipher, SQLite relay замість PostgreSQL/Redis та foreground HTTP polling замість WebSocket+push. Збережено основне: бібліотечна Signal-криптографія, локальні приватні ключі та історія, сервер лише для публічних ключів/маршрутизації/тимчасового шифротексту. Sealed sender, групи, масштабування і незалежний аудит відкладені.
